# Proposal: Move the Hono API into `apps/`

## Why

The monorepo keeps its only two deployable applications in different roots: the TanStack Start web app lives in `apps/web`, while the Hono API — also a deployable application (a Cloudflare Worker) — lives in `server/api`, a leftover from the initial scaffold. This split forces the pnpm workspace to span three globs (`apps/*`, `packages/*`, `server/*`) for what is structurally a two-kind repo (applications and shared packages), and makes the layout harder to predict for anyone adding the next app. Consolidating the API under `apps/api` gives the repo the conventional `apps/` + `packages/` layout with no `server/` exception.

## What Changes

- Move the entire `@finance-application/api` package from `server/api/` to `apps/api/` as a pure relocation — no source, test, migration, or script content changes:
  - `src/`, `tests/`, `scripts/`, `migrations/`, `drizzle.config.ts`, `tsconfig.json`, `vitest.config.ts`, `vitest.workers.config.mts`, `worker-configuration.d.ts`, `wrangler.jsonc`, `package.json`, `turbo.json`, `command-list.md`, `.dev.vars.example`
  - Use `git mv` so file history follows the rename.
- Update `apps/api/wrangler.jsonc`: static-assets `directory` changes from `../../apps/web/dist/client` to `../web/dist/client` (same target, new relative depth). This is the only config content change the move requires.
- Remove the now-empty `server/*` glob from `pnpm-workspace.yaml`; `apps/*` already covers the new location. `server/` is deleted from the repo.
- Keep everything else intact: package name `@finance-application/api`, all npm scripts, the `apps/api/turbo.json` build dependency on `@finance-application/web#build` (the API worker still serves the built SPA), and `tsconfig.json`'s `../../tsconfig.base.json` extends path (same depth at the new location).
- Update documentation and comments that name the old path: `README.md` (structure table, deploy, migrations, env vars, verification sections) and the `server/api/src/schemas` path references in comments across `packages/schemas/src/*.ts`.
- **External manual step (not code)**: the Cloudflare Workers Builds dashboard build root directory must change from `server/api` to `apps/api`. Production deploys fail until the dashboard setting is updated, so it is sequenced into the tasks and called out in the acceptance criteria.
- **BREAKING (developer environment only)**: after the move, contributors' local `server/api/.dev.vars` (untracked, gitignored) no longer sits next to the worker; it must be copied to `apps/api/.dev.vars` for `wrangler dev`. This is documented in tasks; nothing in production is affected.

No API behavior changes: routes, schemas, database schema, migrations, OpenAPI output, and build/deploy artifacts are identical. CI is unaffected — it invokes `turbo run` from the root and references no paths.

## Capabilities

### New Capabilities

- None. This change relocates code; it introduces no new system behavior.

### Modified Capabilities

- None. The relocation preserves every requirement in the existing specs — notably `api-platform` (HTTP behavior) and `web-platform` (the API worker serving the built SPA as static assets), both of which are location-agnostic. This is a pure refactor, so the change declares `skip_specs: true` rather than inventing a requirement to satisfy validation.

## Impact

- **Moved (not rewritten)**: all of `server/api/**` → `apps/api/**`.
- **Workspace config**: `pnpm-workspace.yaml` loses the `server/*` glob; `pnpm-lock.yaml` is regenerated by `pnpm install` (workspace path metadata only).
- **Wrangler**: `apps/api/wrangler.jsonc` assets path is the sole content edit; `wrangler deploy --dry-run` (the existing `build` script) validates it.
- **Cloudflare**: Workers Builds dashboard build root directory must be updated from `server/api` to `apps/api` before the next production deploy; the D1 database, bindings, rate limiter, and worker name are untouched.
- **CI** (`.github/workflows/ci.yml`): no changes — root-level turbo invocation is path-agnostic.
- **Local developer setup**: `.dev.vars` must be manually moved to `apps/api/`; `node_modules/`, `dist/`, and `.turbo/` caches regenerate from `pnpm install` and rebuilt tasks (stale turbo cache entries cannot feed wrong results because turbo hashes inputs including paths).
- **Docs/comments**: `README.md` and `packages/schemas/src/*.ts` comments updated to the new path so future agents don't follow stale pointers.
