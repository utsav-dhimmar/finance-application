# Proposal

## Why

The app has a working API and web shell, but nothing restricts access to it — the finance data this single-user application will hold must belong to an authenticated account. This change adds the first real feature on top of the scaffolds: account registration and session management with Argon2id password hashing and JWT-based sessions (short-lived access token + rotating refresh token), plus the login, register, account, and sign-out UI.

## What Changes

- **API (`server/api`)** — five endpoints under `/api/auth`:
  - `POST /api/auth/register` — create an account (email + password), returns the session
  - `POST /api/auth/login` — verify credentials with Argon2id, returns the session
  - `GET /api/auth/me` — return the authenticated user's `id` and `email`
  - `POST /api/auth/refresh` — rotate the refresh token, return a fresh session
  - `POST /api/auth/logout` — revoke the current refresh token, clear the cookie
- **First database schema**: `users` and `refresh_tokens` tables via Drizzle, with the first D1 migration (generated by drizzle-kit, applied with `wrangler d1 migrations apply --local`).
- **Security primitives**: Argon2id password hashing (via WASM, Workers-compatible) and JWT (HS256) access tokens signed with a `JWT_SECRET` env secret; refresh tokens stored hashed (SHA-256) and rotated on every refresh.
- **Error envelope extension**: new machine-readable codes (`EMAIL_TAKEN`, `AUTH_INVALID_CREDENTIALS`, `UNAUTHENTICATED`, `INVALID_REFRESH_TOKEN`) using the existing envelope shape.
- **Web (`apps/web`)** — `/register` and `/login` pages (shadcn forms), a protected `/dashboard` page showing the authenticated user, an app header with the signed-in email and a Sign out button, session state via TanStack Query, and route guards that redirect unauthenticated visitors to `/login`.
- **Session transport**: HttpOnly, Secure, SameSite=Lax cookies for both tokens — no tokens in JavaScript-accessible storage.

Assumptions recorded: registration is open during development (locking it to exactly one account, matching the single-user mission, is a follow-up decision); password policy is min 8 / max 128 characters; access token lifetime is 15 minutes, refresh token 30 days.

## Capabilities

### New Capabilities

- `user-auth`: Users register an account, authenticate with email and password, stay signed in across visits via rotating refresh tokens, and sign out — spanning the `/api/auth` endpoints, the login/register/dashboard pages, and the web session handling. Owns all authentication behavior end to end.

### Modified Capabilities

- None. The `web-platform` delta lives in the not-yet-archived `scaffold-tanstack-start-web` change; the auth UI adds new behavior (pages, guards, header) without altering that capability's existing landing/not-found requirements, and `api-platform` endpoints are untouched.

## Impact

- **`server/api`**: new `src/db/schema.ts`, `drizzle/` migrations, `src/lib/password.ts`, `src/lib/tokens.ts`, `src/routes/auth/*`, auth middleware; `Env` gains `JWT_SECRET` (`.dev.vars` locally, `wrangler secret` in production); dev dependencies `drizzle-kit`, `@cloudflare/vitest-pool-workers`.
- **`apps/web`**: new routes (`/login`, `/register`, `/dashboard`), `src/lib/api-client.ts`, auth hooks, header component; new shadcn components (`input`, `label`) in `packages/ui`.
- **`packages/ui`**: `input` and `label` components added via the shadcn registry.
- **Existing behavior**: additive only. The landing page, greeting query, and error envelope shape are unchanged; `/api/auth/*` is new surface. Login/register state flows through the existing per-request `QueryClient` and router context.
- **Dependencies introduced**: `hash-wasm`, `hono/jwt` (already in `hono`), `drizzle-kit`, `@cloudflare/vitest-pool-workers`.
